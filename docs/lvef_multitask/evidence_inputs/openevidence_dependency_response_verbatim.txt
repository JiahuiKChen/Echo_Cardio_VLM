## 1. Executive adjudication

**Highest-risk leakage pathways (ranked).**

1. **`tr_mmhg` ← `tricuspid_regurgitant_peak_velocity`.** If `tr_mmhg` is the peak TR gradient, it is exactly ΔP = 4v² with v in m/s and ΔP in mm Hg. This is a closed-form, single-predictor reconstruction — the most severe algebraic leak in `legacy29`. It is only *near*-deterministic if `tr_mmhg` is instead RVSP/PASP, which adds an ordinal RAP term derived from IVC diameter plus respirophasic collapse. Either way, these two must never be co-present, and neither should be scored as an independent target until the raw description of `tr_mmhg` is read.[1][2][3][4][5]
2. **`fs` ← {`left_ventricular_end_diastolic_diameter`, `left_ventricular_end_systolic_diameter`}.** FS = (LVEDD − LVESD)/LVEDD × 100 is exact when both diameters share units, phase convention, and measurement plane. `fs` should not be scored; it is a deterministic function of two other panel members.[6][7]
3. **`lvef` ← linear LV dimensions.** Guideline LVEF is volumetric: EF = (EDV − ESV)/EDV × 100 by biplane disk summation or 3DE. FS and linear diameters are **not** algebraically equivalent to volumetric LVEF, and FS is explicitly criticized as a global-function surrogate. However, if the registry contains a Teichholz/M-mode-derived EF export, LVEF becomes deterministic from LVEDD/LVESD. This is the single most consequential unresolved item and must be checked before any LVEF result is interpreted. Independently, EF-adjacent fields **outside** `legacy29` — EF aliases, LVEDV/LVESV, qualitative LV systolic function, wall-motion summaries, Simpson/3-D outputs, stroke volume, cardiac output — are the likeliest true leak channels and must be searched by name pattern in the restricted registry.[8][9][6][7][10][11]
4. **Ratio reconstruction in the mitral family.** If E/A or E/e′ ratios exist as separate canonical fields, then `mv_peak_e`, `mv_peak_a`, `sept_e_prime`, and `lat_e_prime` each become recoverable from a ratio plus one partner. The panel as listed contains no ratios, but the registry may.[12][13]
5. **LVOT flow chain.** LVOT area = π(D/2)², SV = area × VTI, CO = SV × HR, CI = CO/BSA. `lvot_diam`, `lvot_vti`, `resting_hr`, and `body_surface_area` form a **multivariable deterministic set** for any derived output. Critically, they are *not* algebraic ancestors of `av_pk_vel`: transaortic peak velocity by CW Doppler is a different measurement from LVOT PW flow, coupled only through DVI/AVA if those fields exist.[14][15][16][17][18][1]
6. **Indexing.** Any indexed field (LAVi, LVMi, aortic size index, aortic height index) makes `body_surface_area` or `height_cm` near-deterministically recoverable from the raw dimension.[19][8]

**Family hypotheses that should be revised.**

The provisional families conflate *formula dependency sets* with *clinical correlation families* and should be split accordingly.

- `lv_systolic_geometry` should split into a formula set {`fs`, LVEDD, LVESD} and a correlation set {`lvef`, LVEDD, LVESD} — plus a distinct, currently unenumerated volumetric set {LVEDV, LVESV, `lvef`}.
- `tr_pulmonary_pressure` should split into the exact gradient pair {`tr_mmhg`, TR velocity} and a separate RAP set {`ivc_diam`, IVC collapse} that is only a **partial** input; `ivc_diam` alone is insufficient to derive RAP.[4]
- `rv_structure_function` is too broad: `rv_diam` (structure), `tricuspid_annular_plane_systolic_excursion` (longitudinal function), TR velocity (pressure), and `ivc_diam` (venous filling) are four separate constructs and should not be masked as a block outside strict analysis.[20][4][5]
- `anthropometrics` is not a formula set: BSA requires **height and weight**; height alone cannot derive it.[21][22]
- `hemodynamic_context` should lose `body_surface_area` (an anthropometric, not a hemodynamic, field) and gain an explicit MAP/pulse-pressure sub-set {`resting_sbp`, `resting_dbp`}.[18]
- `aortic_geometry` members are three anatomically distinct levels, not interchangeable; `lv_wall_geometry` is a genuine formula set only for LV mass, and only if `inf_lat_thickness` = posterior wall.[19][23][8]

**Blocked by missing raw metadata.** Whether `tr*mmhg` is a gradient or RVSP; whether `mitral*e*velocity` and `mv*peak*e` are duplicate exports or differ by view/method/units; whether `inf*lat*thickness` is the guideline posterior wall; whether `sinus*diam` and `ascending*aorta*diameter` are distinct levels or one duplicated export; whether any diameters are already BSA-indexed; whether velocities are cm/s or m/s; and whether a Teichholz EF or any EF alias exists. Until these are read, no panel can be locked, and every affected row below stays `Unresolved`.
